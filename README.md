# Elastic ECK Startup Script

Small helper script that boots an Elastic Cloud on Kubernetes (ECK) playground on top of a local [kind](https://kind.sigs.k8s.io/) cluster. It provisions both Elasticsearch and Kibana, exposes them on your host, and prints the `elastic` superuser password so you can log in immediately.

## Requirements

- Docker Desktop (daemon must be running; WSL2 integration if you are on Windows).
- [`kind`](https://kind.sigs.k8s.io/) installed and on `PATH`.
- [`kubectl`](https://kubernetes.io/docs/tasks/tools/) installed and pointed at the default kubeconfig.
- [`helm`](https://helm.sh/) v3.

## Usage

```bash
./install_eck.sh
```

The script is idempotent: if the `kind` cluster already exists it will be reused; the Helm release is upgraded in place.

### Configuration

Override the following environment variables to customize the install:

| Variable       | Default      | Description                                                      |
| -------------- | ------------ | ---------------------------------------------------------------- |
| `CLUSTER_NAME` | `eck-kind`   | Name of the kind cluster the script creates or reuses.          |
| `STACK_VERSION`| `9.0.3`      | Elastic Stack version used for both Elasticsearch and Kibana.   |
| `NAMESPACE`    | `elastic`    | Kubernetes namespace where Elasticsearch and Kibana are deployed. |

Example:

```bash
CLUSTER_NAME=eck-lab STACK_VERSION=8.13.4 ./install_eck.sh
```

## What the Script Does

1. Verifies that Docker, kind, kubectl, and helm are installed and that Docker is reachable.
2. Creates a single-node kind cluster (if needed) with NodePort mappings so that:
   - Elasticsearch is reachable on `https://localhost:9200`.
   - Kibana is reachable on `https://localhost:5601`.
3. Installs/updates the Elastic ECK operator via Helm into the `elastic-system` namespace.
4. Deploys a one-node Elasticsearch cluster and a single Kibana instance in the target namespace.
5. Waits for Elasticsearch health to become `green` and for Kibana to roll out.
6. Prints the autogenerated `elastic` user password and a short connection summary.

## Accessing the Stack

- Elasticsearch: `https://localhost:9200`
- Kibana: `https://localhost:5601`
- Username: `elastic`
- Password: printed at the end of the script execution

> Certificates are self-signed, so browsers and API clients will warn you until you accept the risk or configure trust.

## Cleanup

Remove everything by deleting the kind cluster:

```bash
kind delete cluster --name "${CLUSTER_NAME:-eck-kind}"
```
